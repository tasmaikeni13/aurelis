# Phase 9 — Independent reproduction and publication audit

Depends on phases 0–8 or an explicitly documented negative-result endpoint.

## Adaptive start gate

The release audit validates a complete revision, not a collection of passing
old phases. Any unresolved STALE dependency, changed theorem premise, changed
evaluator, or mixed artifact revision blocks release. If reproduction finds a
repair, update the canonical documents and manifest, mark the affected closure
STALE, and return to the earliest affected phase before rewriting the paper.

## Deliver

Reproduce core numerical/formal results and a representative trained/serving
comparison in a clean environment. Resolve every paper claim to an equation,
Lean theorem with premises, measured artifact, or clearly labeled hypothesis.
Pin all source/data/checkpoint versions, configs, seeds, commands and hashes.

Re-run the primary-literature search. Compare the actual final mechanism with
ResKV, Quest/RetrievalAttention, certified attention, NHA, Gated DeltaNet and
current optimized hybrids. An unsearched conjunction is not established novelty.
If another method subsumes the contribution, narrow or withdraw priority claims.

Rewrite the final manuscript around what survived, including negative results,
hardware scope, total resource use, failure rates, arithmetic-proof coverage,
and local versus trajectory-level guarantee boundaries. Keep historical v1
evidence quarantined and retain the audit explaining why it was not reused.

## Release gates

No hard-coded task scores or fabricated hardware/timing. All tables/figures
derive from saved measurements. All Lean statements compile without admitted
goals or project axioms. No theorem is cited for quality, runtime, finite
precision, or whole-model safety it does not prove. Implementations and scripts
must match the published theory revision.

Publish an honest qualified result or negative result. A successful reproduction
audit can PASS even when the scientific hypothesis failed, but the paper must
say so and must not claim deployment readiness. Include a concrete implementation
and deployment checklist of any remaining limitations.
